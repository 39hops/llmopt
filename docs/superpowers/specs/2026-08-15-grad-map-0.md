## Object

x signature(failure family j), over frozen checkpoints. Rows =
train families (i_heurisch, non-heurisch remainder, sympy atoms,
axiom atoms, stock chains, per-level slices L3-L7). Columns =
per-level failure populations.

[AMENDED — failure column re-based] The original column ("the 17

checkpoint, BIRTH_SEED=2 — a different lineage from every atlas

Failure prompts are lineage-independent (problem i =
_gen_isolated(lv, 9_900_000 + 1000*lv + i), gate.py:121);

SIGALRM). The m015300/17 set may be read as a disclosed
cross-lineage rider, never as the gate column.

## Pre-registered metric set (fixed BEFORE any retrodiction look)

1. raw gradient cosine (family mean gradient v failure mean
   gradient)
2. Adam-preconditioned cosine. [AMENDED — pinned pre-look] No
   atlas checkpoint carries optimizer state (all five save
   model.state_dict() only: birth19m_atoms_{ladder,dose,rule}.py
   torch.save lines), so the "where available" branch is empty and
   the proxy IS the metric. Pinned construction: accumulate
   v_proxy = running mean of g^2 over K=50 batches of the
   signature checkpoint's OWN training stream (forward/backward
   only, no weight updates, same process), then precondition by
   1/sqrt(v_proxy + 1e-8). No optimizer steps anywhere — the mps
   fence's valid shape.
3. gradient norm per family (scale context, not a ranking metric)
4. projection of family mean gradient onto failure mean gradient
5. pairwise interference within family: mean g_i . g_j over row
   pairs (redundancy/conflict)
6. layerwise variants of 1 and 4 (late layers separately — the
   recognition story predicts late-layer concentration)
7. one low-rank random projection (fixed string-seeded matrix) for
   cheap storage of per-row signatures

No metric added or dropped after the first retrodiction number is
seen. If the set fails, the instrument fails; a new set is a new
pre-registration.

## Fences

- Desk instrument; signatures are device-local (Mac); no
  cross-device signature comparisons.
- Never score by weight distance (house law) — everything here is
  gradient-space at a fixed checkpoint, function-adjacent but not
  function-verified; any shard the atlas picks is validated only
  by a birth + gate.
- Failure gradients use teacher-forced loss on failure prompts
  with their booked reference answers — a proxy for "what would
  fix the failure"; disclosed in every readout.
- mps nondeterminism (AMENDMENT SOFT-SPEED-1-PRECONDITION):
  signature computation is forward/backward without optimizer
  steps — verify repeatability of the signatures themselves (two
  passes, cosine of cosines) before trusting any ranking.
  [AMENDED — protocol pinned] The two passes run in the SAME
  process (the fence's valid paired shape; cross-process identity
  is the thing the amendment declared impossible). Report the
  repeat cosine PER PARAMETER GROUP, embedding separately — the
  suspected nondeterminism class is scatter-add in embedding
  backward, and a near-1.0 global number must not hide an
  unusable embedding row. Gate on the ranking scale: if
  between-family cosine separation is inside the repeat noise,
  the gate is UNRESOLVED regardless of sign, and books as such.
- Receipts: new path logs/gradmap0/ (never append to frozen
  receipt dirs); smoke rows go to smoke.jsonl, never the real
  receipt file; provenance fields (shard, checkpoint, ckpt sha,
  family) DERIVED from the artifacts actually opened, never
  literals — the RULE-ABLATE false-emitter class.
- Cost triage first (/probe habit): one-family timing probe
  before committing to the full matrix; the matrix is ~6
  checkpoints x ~10 families x 2 passes and is not free on a
  Mac.
